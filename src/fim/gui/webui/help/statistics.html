Statistics reference

Select a statistic's underlined name in a desktop statistics table to open its definition here. The value and its full-precision tooltip remain in the table; the color swatch controls whether its trajectory is plotted. This reference is available in the application without a network connection. Links to model background, specialized derivations, and the Python API open in your browser and require access to the repository.

Each entry gives the reported identifier, interpretation, formula, and implementation. For a scripted analysis, start with the Python guide. This page documents all supported statistics; API links lead to their implementation documentation, which includes source links.

Notation and aggregation

Mathematical symbols and formulas use TEX; literal settings, API identifiers, and reported keys use backticks. Displayed equations have unique tags beginning with S. Section headings retain the reported keys so desktop help links continue to identify each entry.

The desktop science views use the mathematical symbols, including in tooltips, result messages, and chart readouts. For example, the saved key H_ST is displayed as HST, Delta as δG, and MI as I. Native selection menus cannot reliably typeset scripts; their text spells out "subscript" or "superscript", with the selected mathematical symbol shown alongside. Configuration fields, command-line arguments, and saved JSON/CSV keys retain their literal identifiers.

For one locus, pi,a is the frequency of allele a in deme i, d is the number of demes, and wi is a normalized deme weight. The weights satisfy wi≥0 and ∑i=1dwi=1. Frequencies sum to 1 within each deme. The pooled frequency is:

pa=∑i=1dwipi,a(S.1)

Unless stated otherwise, formulas below use equal deme weights, wi=1/d, as the simulator's reports do. The deme_weighting setting applies only to E_ST, Delta, and MI; size weights these measures by deme size. It does not change the weighting of the other reported measures.

The formulas define statistics of population frequencies, not finite-sample estimators. N in the model's mathematics denotes gene copies; the desktop population field counts individuals and applies the selected ploidy.

Locus and time aggregation are separate operations. In the default multilocus report, D and G_ST use ratios of mean heterozygosities; averaging per-locus ratios is a different estimand. The other measures follow their documented aggregation rules. A convergence estimate may also average over generations, and a batch summary averages across replicates. Consult the report API, output schemas, and convergence reference before comparing these quantities. An undefined value is not evidence of zero differentiation.

D

Jost's frequency-weighted allelic differentiation:

D=dd−1HT−HS1−HS(S.2)

With equal deme weights, 0 denotes identical allele frequencies and 1 denotes disjoint allele sets. D is not a measure of nearness to fixation.

Python API: jost_d

G_ST

Nei's heterozygosity ratio:

GST=HT−HSHT(S.3)

Its interpretation depends on within-deme diversity; high allelic differentiation need not imply high GST. The statistic is undefined when HT=0, including fixation for the same allele in every deme.

Python API: g_st

H_S

Mean within-deme expected heterozygosity:

HS=∑i=1dwi(1−∑api,a2)(S.4)

It is the probability that two independent gene copies drawn within a deme carry different alleles, averaged over demes.

Python API: h_s

H_T

Expected heterozygosity of the pooled allele-frequency distribution:

HT=1−∑apa2(S.5)

Pooling includes both within- and between-deme variation; it is not the mean of the individual deme heterozygosities.

Python API: h_t

H_ST

Partitioned between-deme heterozygosity:

HST=HT−HS1−HS(S.6)

It satisfies the partition identity:

HT=HS+HST−HSHST(S.7)

With equal weights, D=dHST/(d−1). This is not Hedrick's standardized GST′.

Python API: h_st

E_ST

Entropy differentiation:

EST=ST−SSSw(S.8)

Here ST is pooled Shannon entropy, SS is the weighted mean within-deme entropy, and Sw is the entropy of the deme weights:

Sw=−∑i=1dwiln(wi)(S.9)

With equal weights, Sw=ln(d). Entropy weights rare alleles more strongly than heterozygosity does. The deme_weighting setting controls the weights for this measure.

Python API: e_st

K_ST

Allele-number differentiation:

KST=AT/AS−1d−1(S.10)

Here AT is the number of distinct alleles in the pooled population and AS is the mean number present per deme. Presence means strictly positive frequency. These are order-zero allele counts, not the effective counts displayed below. Equal deme weights are required.

Python API: k_st

A_CGD

Caballero-Garcia-Dorado allelic distance. For a pair of demes, count alleles present in exactly one deme and divide by 2; A_CGD is the mean over distinct unordered pairs. Frequencies affect presence but do not otherwise weight the distance. This is a count, not a proportion.

Python API: allelic_distance

Delta

Gregorius's distance-oriented differentiation, displayed as ΔG. Compare each deme's frequency vector with the weighted mixture of all remaining demes using total variation distance

TV(pi,prest,i)=12∑a|pi,a−prest,i,a|(S.11)

Here prest,i,a is the frequency of allele a in the weighted mixture excluding deme i. Average the distances over demes. The mixture and outer average use the configured deme weights. For two equally weighted demes, this is their total variation distance. For more than two, it is not the average of all pairwise distances.

Python API: gregorius_delta

MI

Allele-by-deme mutual information, displayed as I:

I=ST−SS(S.12)

Units are nats. It measures the statistical association between allele identity and deme membership. Dividing by deme-weight entropy gives E_ST; MI itself is not normalized to the unit interval. The entropies in this calculation use the configured deme weights.

Python API: mutual_information

Gs

Within-deme gene identity, reported as Gs:

Jwithin=1−HS(S.13)

Sampling is with replacement. Identity here means identity in allelic state, not a recorded pedigree relationship.

Mathematical guide · Python API: gs

Gd

Mean between-deme gene identity. With equal weights,

Jbetween=d(1−HT)−(1−HS)d−1(S.14)

This quantity is reported as Gd. It is the mean probability of an allelic match between gene copies drawn from distinct demes.

Mathematical guide · Python API: gd

D_m

Nei's mean pairwise between-deme gene diversity:

Dm=dd−1(HT−HS)(S.15)

Unlike D, it does not divide by within-deme identity. Equal deme weights are required.

Python API: d_m

R_ST

Nei's relative between-deme diversity:

RST=DmHS(S.16)

It is undefined when HS=0. This identifier denotes Nei's diversity ratio, not the similarly named microsatellite statistic based on allele-size variance.

Python API: r_st

G_ST_NEI_LOG

Nei's logarithmic GST′:

GST,Nei′=ln(JS/JT)−ln(JT)(S.17)

Here JS=1−HS and JT=1−HT. This is distinct from Hedrick's standardized statistic despite their shared notation. The reported value is undefined at HT=0 or HS=1.

Python API: g_st_log

G_ST_HEDRICK

Hedrick's standardized GST′ divides by the attainable maximum:

GST,Hedrick′=GSTGST(max)(S.18)
GST(max)=(d−1)(1−HS)d−1+HS(S.19)

It rescales GST by its maximum at the given within-deme diversity and deme count. The report returns an undefined value when G_ST is undefined.

Python API: g_st_prime

F_ST

Overall coancestry-based fixation index:

FST=Jwithin−Jbetween1−Jbetween(S.20)

The report uses equal deme weights and pooled heterozygosities across loci. It returns an undefined value when Jbetween=1.

Python API: derived_differentiation

F_ST_PAIR

Pairwise coancestry-based fixation index for the selected demes:

FST,pair=(JX+JY)/2−JXY1−JXY(S.21)

Here JX=∑apX,a2, JY=∑apY,a2, and JXY=∑apX,apY,a. Only the selected pair contributes. The implementation returns 0 when both demes are fixed for the same allele.

Python API: pairwise_f_st

Nei distances

The NEI_I_* identifiers report normalized gene identity, I; NEI_D_* report distance:

DNei=−ln(I)(S.22)

These distances are distinct from Jost's D. The symbol I in this section denotes Nei identity, not the mutual information in (S.12). Each identifier specifies three choices:

Identifier part Meaning
PAIR The two demes selected for the scatter plot
ALL All demes, with equal weight
GEO Geometric mean of within-deme identities in the denominator
ARITH Arithmetic mean in the denominator
No suffix Average identities over loci, then compute the ratio
LOCUS_MEAN Average per-locus distances; the corresponding identity is their geometric mean

For a pair, the GEO and ARITH identities are, respectively:

Ipair,geo=JXYJXJY(S.23)
Ipair,arith=JXY(JX+JY)/2(S.24)

The all-demes forms use mean between-deme identity in the numerator and the specified mean of all within-deme identities in the denominator.

No shared alleles gives I=0 and infinite distance. With LOCUS_MEAN, one locus with zero shared identity makes the mean distance infinite. For more than two demes, the geometric normalization can produce I>1 and negative distance when deme diversities differ. These values are properties of that normalization, not negative evolutionary time. Saved JSON represents non-finite distances as null; the desktop displays infinity explicitly.

Effective allele counts

The displayed HDS and HDT are inverse-concentration effective allele counts:

HDS=11−HS(S.25)
HDT=11−HT(S.26)

Explore uses A_S and A_T for these predicted counts. They give the number of equally frequent alleles with the same heterozygosity, not the number of distinct allele labels and not effective population size.

Python API: effective_allele_count

Entropy

Explore's S_S reports mean within-deme Shannon entropy SS, and S_T reports pooled Shannon entropy ST. For frequencies pa, entropy is:

S=−∑a:pa>0paln(pa)(S.27)

Zero-frequency terms are omitted. Units are nats. Explore shows theoretical predictions under the assumptions stated in its model description, not measurements from a saved trajectory.

Python API: theory_for_configuration

Identity recovery

Explore's retention rate, equilibrium identity, and half-life describe the mutation-negligible identity-recovery approximation. The retention rate controls the exponential approach to the predicted identity; the half-life is the generations required to halve the departure from that equilibrium. These are theoretical predictions, not fitted convergence times.

The Run card's trajectory graph offers the same approximation as an opt-in overlay: f₀, drawn from a founder event (identity by descent starting at 1) recovering toward equilibrium under migration alone, at this configuration's own N and m. Off by default (the "f₀ (identity recovery)" checkbox beside the graph; set_show_identity_recovery_ trajectory), because — like Explore's own numbers above — it is a closed-form reference computed from the configuration alone, not a measurement of the run it is drawn beside: it assumes zero mutation and a single common ancestor at generation zero, neither of which a typical run's own settings need match.

Worked example: two demes and two alleles

This example uses one locus and equal deme weights. Deme X has frequencies (3/4,1/4) for alleles A and B; deme Y has (1/4,3/4). Pool the two demes by averaging each allele's frequency:

pA=1234+1214(S.28)

Thus pA=1/2; the same calculation gives pB=1/2. To find within-deme identity, square the frequencies and add:

JX=(34)2+(14)2(S.29)

This gives JX=10/16=5/8. Reversing the frequencies gives JY=5/8 too, so their mean is Jwithin=5/8. Its complement is HS=1−5/8=3/8. For the pooled population:

JT=(12)2+(12)2(S.30)

Thus JT=1/2 and HT=1/2. The excess pooled heterozygosity is HT−HS=1/8. Substituting in (S.2) and (S.3) gives:

D=211/85/8(S.31)
GST=1/81/2(S.32)

The results are D=2/5=0.4 and GST=1/4=0.25. Both use the same numerator, but different denominators; they are not interchangeable scales of the same reported number.

For between-deme identity, multiply matching allele frequencies across demes rather than squaring frequencies within a deme:

JXY=3414+1434(S.33)

This gives Jbetween=JXY=3/8. The coancestry index is:

FST=5/8−3/81−3/8(S.34)

It evaluates to 2/5. Equality with D in this example is not a general identity. Since the two within-deme identities are equal, their arithmetic and geometric means both equal 5/8, giving:

Ipair=3/85/8(S.35)

Thus Nei identity is 3/5, and its distance is:

DNei=−ln(3/5)(S.36)

The distance is approximately 0.510826. The logarithm turns identity into a distance; it does not make this number equal to Jost's D.

Entropy uses logarithms of the individual frequencies, not their squares. Both demes have the same entropy:

SS=−34ln(3/4)−14ln(1/4)(S.37)

This is approximately 0.562335 nats. The pooled entropy is ST=ln(2), approximately 0.693147 nats. Their difference is mutual information:

I=ln(2)−[−34ln(3/4)−14ln(1/4)](S.38)

Here I is approximately 0.130812 nats, not the Nei identity 3/5 above. Normalizing by Sw=ln(2) gives:

EST=Iln(2)(S.39)

The result is approximately 0.188722. Finally, both alleles occur in both demes, so KST=0 and the reported allelic distance A_CGD is 0 despite the frequency differences. In contrast, the total variation distance is (|3/4−1/4|+|1/4−3/4|)/2=1/2. These measures answer different questions about the same frequencies.
