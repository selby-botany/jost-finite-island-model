Mathematical quantities use TEX, such as τ for a relaxation time. Literal configuration keys, report fields, and Python names use backticks, such as precision and standard_error. Equations are numbered within this document as (C.1), (C.2), and so on; the prefix means convergence reference, not Appendix C of the simulator design. That design's Appendices C–F provide additional algebra, probability, and linear-algebra refreshers. Statistic definitions and saved-result identifiers are listed in the statistics reference.

If you only read one section

A run first completes a burn-in, the period during which the initial condition's influence decays. It then collects an evidence window until the estimated average reaches the requested precision (precision at the specified confidence). The report includes the estimated average and its uncertainty. If the generation cap is reached first, the run reports that status and the uncertainty achieved. A short run does not by itself demonstrate equilibrium. Check convergence_burn_in, max_generations, and the reported uncertainty against the model's timescale.

There are two separate questions:

  1. Has the initial condition's influence decayed enough? Burn-in addresses this possible bias.
  2. Has enough evidence been collected to estimate the equilibrium average precisely? The averaging window and its error bar address sampling uncertainty.

A long burn-in does not automatically answer the second question. A small error bar does not repair a burn-in that ended too early. The population need not stop changing for its equilibrium average to be estimable.

Why does my run take so long?

Interpretation

Population structure changes over generations through migration, mutation, and drift. Low migration can produce long relaxation times, often tens of thousands of generations. Drift continues to cause generation-to-generation variation at equilibrium; the evidence window estimates the average to the requested precision.

Set convergence_burn_in and max_generations to auto to use the model-derived values. The app displays the expected burn-in next to the Run simulation button before execution, for example:

Convergence: burn-in 104,338 generations, cap 399,728 (derived; this model needs about 19,693 generations to forget its starting state)

If a run reaches the cap before meeting its precision criterion, the report gives the achieved uncertainty. Possible responses include increasing the generation cap, accepting a wider interval, adding independent loci, or using multiple replicates. Parallel execution can reduce elapsed time, but each replicate incurs its own burn-in, so a batch need not reduce total computation.

Quick reference

Setting Default Meaning
precision 0.01 Plus or minus, in each watched statistic's own units, at confidence
confidence 0.95 Nominal coverage of the interval procedure (0.90, 0.95 or 0.99), not a guarantee about one interval
convergence_burn_in auto First included generation, derived from ⌈kτ⌉ with k=max(5,ln(2/ε))
max_generations auto Safety cap: max(200000,b+⌈15τ⌉), at most 10,000,000

ε denotes precision, b the derived burn-in boundary, and τ the estimated relaxation time of the slowest locus. The table gives the base identity-statistic policy; an expert multiplier can lengthen burn-in for spectrum statistics. Its shipped value is 1, so enabling a spectrum statistic alone does not currently extend burn-in. Any valid explicit integer you write replaces the derived value. If you set only one of the two, the other adapts: a derived cap leaves 15τ after an explicit burn-in, subject to the 10,000,000-generation ceiling. The expert: mapping changes the policy constants (the floor of 5, the factor 15, the first check, the effective-sample-size floor and the rest; see configuration.md).

Related settings, each described in configuration.md: convergence_statistic (default D and G_ST, stopping when both have settled; any global statistic may be watched, an unbounded one such as an allele count gets a relative precision), statistic_precision (a plus-or-minus for one statistic), convergence_estimate (mean of values or value of means, below), precision_method and replicate_averaging_window (batches, below), and trajectory_retention (thin a very long run's trajectory file).

Symptoms of a bad value:

  • Burn-in too short: the average starts inside the transient and is biased.
  • Cap too small: the run ends "hit the cap", possibly before the burn-in even ends (then there is no average at all); the run logs a warning.
  • Cap too large: only a run that never reaches its precision takes longer to end.

fim run prints the derived values unless --quiet. They are also written as plain integers to manifest.json. Reusing them preserves the schedule; exact trajectory reproduction additionally requires the seed, model parameters, software version, and compatible numerical platform.

How a run decides it is finished

For sysops, technicians and developers.

resolve burn-in and cap from configuration or model-derived defaults
start the evidence window at the burn-in boundary, excluding generation 0
first check after the configured initial evidence span
at each check, for every watched statistic:
    estimate its mean, standard error, and effective sample size
    pass if both the error target and the effective-sample-size floor pass
stop if all (or any, under `convergence_combinator: any`) pass
otherwise grow the evidence window before the next check
stop as capped at max_generations
  • Nothing is averaged before the burn-in, and generation 0 is never in an average.
  • z is the two-sided normal critical value (about 1.96 at 95%), so precision keeps the meaning "plus or minus this much".
  • The effective sample size, reported as effective_sample_size, is how many independent values the window's correlated generations are worth; a standard error from fewer than 50 is not trusted by the default rule. Geyer's initial positive sequence estimator sums an estimated sequence of autocorrelations up to a data-dependent cutoff, rather than using only neighboring generations (see How precise is the reported value?).
  • Every watched statistic is judged at every check, so the stop generation never depends on the order they are listed in.
  • With no relaxation time (no migration and no mutation, or an explicit matrix beyond 24 demes) and convergence_burn_in: auto, the window starts at the first tenth of the run at each check.
  • At the stop, every recorded statistic, watched or not, gets its mean and standard error over the same window, in report.json's window_statistics.

Window boundaries and check scheduling

Let t be the current generation and b≥1 the first included generation. The evidence window includes both endpoints:

W=t−b+1(C.1)

W counts observations, not elapsed gaps between them. If b=100 and t=150, the window contains 51 observations: generations 100,101,…,150. Generation 99 is excluded. The name burn_in is therefore best read as a boundary; it does not mean that generation b is discarded too.

With default expert settings and an available τ, the initial span and first check are:

Δ0=max(50,⌈2τ⌉)(C.2)
t0=b+Δ0(C.3)

The ceiling ⌈x⌉ means round upward to a whole generation. For b=100 and τ=20, the maximum in (C.2) chooses 50 rather than 40, so the first check is at generation 150. If that check fails, the implementation schedules:

tnext=max(t+1, b+⌈gW⌉),g=2(C.4)

Here g is the default growth factor. For the 51-observation window above, the next check is at 100+2·51=202, which includes 103 observations. This endpoint convention explains why "double the window" is a description of the policy rather than an exact doubling of the observation count. The run still ends at its cap if a scheduled check lies beyond it.

See the check-scheduling limit for the consequences of checking only at selected generations.

When no model-derived time is available, the fallback boundary at a check is ⌊0.1t⌋. Only generation-1 and later values are recorded by the run for this averaging. The floor ⌊x⌋ rounds downward. Unlike a fixed burn-in, this window's start moves as the run grows; it is a fallback policy, not a demonstrated equilibrium time.

How the numbers are derived

For developers and reviewers.

Units and the scalar island approximation

Let Nk count individuals in deme k, c count gene copies per individual from ploidy, and nk=cNk count copies at one locus. The total copy count is:

ntotal=∑k=1dnk(C.5)

Do not add copies across loci. Twenty diploid demes of 225 individuals have nk=450 and ntotal=9000 at each locus. For the scalar island model, each destination keeps fraction 1−m and receives fraction m from the other demes. With equal sizes and m>0, the implemented approximation is:

T=ntotal+d−12m(C.6)
τ=12μmin+1/T(C.7)

T is a pairwise ancestral coalescence timescale: time for two lineages to reach a common ancestral copy. It is not the final generation number, nor the time for every copy's entire genealogy to coalesce. μmin=minlμl is the smallest per-locus mutation probability, supplied by mu or derived from mu_b. With shared sizes and migration, the lowest mutation rate gives the slowest-decaying identity mode and sets the common burn-in scale.

The denominator in (C.7) is a sum of rates, each in inverse generations. Its reciprocal is in generations. Adding the times T and 1/(2μmin) would instead describe waiting for two successive events, not two alternative ways to forget identity. These are discrete-generation, small-rate approximations, not exact identities for arbitrary migration and mutation probabilities.

For five haploid demes of 100 copies each, m=0.0001 and μmin=0.000001, calculate:

T=5·100+5−12·0.0001=500+20000=20500(C.8)
τ=10.000002+1/20500≈19692.60(C.9)

The small rate 0.000002 is added to approximately 0.00004878. The resulting decay is slow even though a generation is cheap to simulate. At m=0, the implementation sets the coalescence-rate contribution to zero without dividing by zero. Positive mutation then gives τ=1/(2μmin). With both rates zero this route has no finite time and refuses a derived cap.

The relaxation time is computed whenever a supported model permits it, not only when burn-in or cap is automatic. Explicit matrices and unequal sizes use the identity operator in the next section, with a d2-by-d2 eigenproblem limited to 24 demes. The source is defaults.py.

The relevant limits are the scalar approximation, unequal sizes and the eigenproblem guard, selection of the slowest locus, and the high-migration reference scenario.

From a decay scale to a burn-in

Let ε>0 denote requested precision. A unit-amplitude mode that decays exponentially has remaining magnitude exp(−b/τ) after b generations. Allocate half the requested precision to that residual as a policy heuristic:

exp(−b/τ)≤ε/2(C.10)

Taking natural logs, which preserve inequalities between positive numbers, gives:

−b/τ≤ln(ε/2)(C.11)

Multiplication by the negative number −τ reverses the inequality:

b≥τln(2/ε)(C.12)

The implementation adds a minimum multiple:

k=max(5,ln(2/ε))(C.13)
b=max(1,min(Cmax,⌈akτ⌉))(C.14)

Cmax=10000000 is the default hard ceiling. a=1 for the base identity-statistic policy; watching an allele-spectrum statistic can invoke spectrum_burn_in_multiplier instead. The floor of five relaxation times prevents a loose precision from shortening the burn-in too much. In the measured two-mode example motivating the policy, bias at about 5.3τ was −0.00016; that measurement is evidence for a default, not a universal bound.

For ε=0.01, ln200≈5.298317, so the logarithm exceeds the floor. With (C.9) and a=1, b=⌈104337.661877…⌉=104338. For ε=0.001 the multiple grows to ln2000≈7.600902. For ε=0.1 it stays at five because ln20<5. Zero precision is handled specially: the derived burn-in reaches the ceiling rather than evaluating ln(2/0).

The unit-offset argument explains the policy; it is not a proof that every nonlinear statistic's bias is bounded by ε/2. Mode amplitudes, nonlinear ratios, mutation model, and clipping at the ceiling limit that interpretation. In particular, clipping a requested burn-in cannot preserve a bound that required a longer run.

From burn-in to a safety cap

The base derived cap is:

C=min(Cmax,max(200000,b+⌈15τ⌉))(C.15)

For the same example, ⌈15τ⌉=295390 and C=104338+295390=399728. The 200,000 floor does not apply because that sum is larger. For a much faster model it can dominate. The GUI example near the start of this document uses these values; (C.8)–(C.15) show the precise arithmetic for the stated example.

The floor is empirical, not derived from τ. Measurements of single-locus D at target precision 0.01 needed close to 130,000 generations in two regimes with τ near 85 and 19,693. Fifteen relaxation times alone would leave too little averaging in the fast regime. Conversely, the cap is not a promise that the precision will be reached: the uncertainty check still decides.

See the empirical-cap limit for the scope of the measurements supporting the floor.

Where the formula comes from

For the mathematically curious. The only linear algebra needed is explained here.

One number: follow the error instead of the state

Start with a deterministic recurrence:

xt+1=λxt+c0,0<λ<1(C.16)

t counts generations, λ is the fraction of the old value retained, and c0 is a constant addition. The subscript distinguishes this constant from ploidy c. A fixed point x* is a value that the recurrence leaves unchanged. Substituting it gives x*=λx*+c0. Subtract λx* and divide:

x*=c01−λ(C.17)

Now define the error et=xt−x*. Subtract the fixed-point equation from the update. The constant terms cancel:

et+1=λ(xt−x*)=λet(C.18)

Apply that rule twice to obtain e2=λ2e0; repeat t times:

et=λte0(C.19)

For λ=0.9, c0=0.02, and x0=0.8, the fixed point is 0.2 and the initial error is 0.6. The next two states are 0.74 and 0.686, whose errors 0.54 and 0.486 are exactly 0.9 times their predecessors. After ten steps the error is 0.6(0.9)10≈0.20921.

An exact exponential decay scale solves λτ=e−1:

τlog=−1lnλ(C.20)

This follows by taking logs: τlnλ=−1. The code uses a closely related gap timescale:

τgap=11−λ(C.21)

To connect them, put δ=1−λ. For small δ, ln(1−δ)≈−δ, so (C.20) is approximately 1/δ, which is (C.21). At λ=0.9 the scales are about 9.4912 and 10 generations. At λ=0.5 they are about 1.4427 and 2, so the approximation is less close. This document uses τ for the implemented timescale; it does not identify the two definitions as exactly equal.

For a single positive mode the gap choice is conservative relative to the exact exponential scale, because lnλ≤−(1−λ) implies λt≤exp[−t(1−λ)]. That inequality does not by itself bound every multivariate nonlinear statistic.

Many numbers: eigenvectors are shapes that keep their shape

A vector collects several quantities. A matrix specifies which weighted combinations form their next values:

xt+1=Axt+c(C.22)

This is an affine update: a linear transformation plus a constant vector. Subtracting its fixed point again cancels the constant, leaving et+1=Aet. An eigenvector v≠0 is a direction that the matrix scales without changing its shape:

Av=λv(C.23)

For example, take:

A=(0.80.10.10.8)(C.24)

Multiplication gives two particularly simple directions:

A(11)=(0.90.9)=0.9(11)(C.25)
A(1−1)=(0.7−0.7)=0.7(1−1)(C.26)

The first direction moves the coordinates together; the second moves them oppositely. Their eigenvalues, 0.9 and 0.7, are the retained fractions per step. Decompose one initial error:

(0.60.2)=0.4(11)+0.2(1−1)(C.27)

Applying A once gives (0.50,0.22)T: the common component becomes 0.4·0.9=0.36 and the contrast becomes 0.2·0.7=0.14. Applying it t times gives:

et=0.4(0.9)t(11)+0.2(0.7)t(1−1)(C.28)

The faster contrast vanishes sooner. The slow common component dominates later, provided it was present in the initial error and the measured quantity can see it.

Starting discrepancy
    +-- common component, multiplied by 0.9 each step --+
    |                                                   +--> sum at step t
    +-- contrast component, multiplied by 0.7 each step -+
             fades sooner

The spectral radius ρ is the largest absolute eigenvalue:

ρ(A)=maxj|λj|(C.29)

The implementation takes τ=1/(1−ρ), provided ρ<1. A radius of one leaves a nondecaying mode and no finite derived time. The eigenvector decomposition above applies directly when there is a full basis of eigenvectors, as in this example. More general matrices can have transient effects or polynomial factors as well as exponential decay; the radius describes an asymptotic rate, not a universal finite-time error bound.

Pairwise identity: why two migration weights appear

Fix one locus under infinite alleles. For a realized frequency table, define Jij=∑api(a)pj(a): the probability that independent draws from demes i and j have the same label. On the diagonal, both draws are from the same distribution with replacement. They can select the very same physical copy, so this is frequency identity, not distinct-copy identity F in the simulator design.

Equilibrium here concerns matching probabilities and frequency structure, not an unchanging set of absolute allele IDs. See the allele-label stationarity limit.

For a deterministic row-stochastic parental mixing matrix M, the post-migration identity table is:

K=MJMT(C.30)

The superscript T means transpose: interchange rows and columns. It is not a generation index or the coalescence time T. To see why both sides are needed, expand one entry:

Kij=∑r=1d∑s=1dMirMjsJrs(C.31)

The first offspring's parent comes from source r with weight Mir; the second comes from source s with weight Mjs. For that source pair, labels match with probability Jrs. Multiply these factors, then add over every possible source pair. Mixing a single allele-frequency row needs one weight; matching two sampled copies needs two.

This derivation uses a deterministic M. See the stochastic-migration limit before applying it to randomly drawn migrant fractions.

For a concrete calculation, use:

M=(0.80.20.10.9)(C.32a)
J=(0.680.320.320.68)(C.32b)

The J table comes from frequency rows (0.8,0.2) and (0.2,0.8), so it is an actual identity table rather than an arbitrary collection of probabilities. First multiply on the left:

MJ=(0.6080.3920.3560.644)(C.33)

For example, the upper-left entry is 0.8·0.68+0.2·0.32=0.608. Now mix the second parent with the transposed matrix:

K=(MJ)MT=(0.56480.41360.41360.6152)(C.34)

Its upper-left entry is 0.608·0.8+0.392·0.2=0.5648. As a separate check, MP gives frequency rows (0.68,0.32) and (0.26,0.74). Their squared sums and cross-product give exactly (C.34). Unlike M and P, rows of J or K need not sum to one. Their entries are separate matching probabilities, not alternatives partitioning a single draw.

Drift and mutation: distinguish self-pairs from distinct pairs

Write the probability that two independently selected copies both avoid mutation as:

α=(1−μ)2=1−2μ+μ2(C.35)

For distinct copies in different demes, independent mutation can preserve a match only when both avoid mutation:

E[Jij′∣P]=αKij,i≠j(C.36)

The prime denotes the next generation. The expectation averages over drift and mutation conditional on the current frequency table P. Fresh infinite-alleles mutations cannot match another copy's label.

That assumption is essential. See the finite-alleles limit for recurrent mutations that can create matching labels.

For two draws within destination i, the chance of selecting the same observed offspring copy twice is 1/ni. Such a self-pair always matches, even if that offspring mutated. Otherwise two distinct offspring must both avoid mutation and have matching parental labels:

E[Jii′∣P]=1ni+(1−1ni)αKii(C.37)

This order of factors matters. Multiplying the entire right-hand side by α would incorrectly allow mutation to make a copy different from itself. The actual engine still executes Migrate → Drift → Mutate; (C.36)–(C.37) summarize its matching probabilities, not a proposed rearrangement of the operators.

For (C.34), take n1=n2=10 and μ=0.1, so α=0.81. The upper-left output is 0.1+0.9·0.81·0.5648=0.5117392. The off-diagonal output is 0.81·0.4136=0.335016. The full conditional expectation is:

E[J′∣P]=(0.51173920.3350160.3350160.5484808)(C.38)

This table is not one random output population. It is the mean identity table over possible next populations. Linearity lets the same recurrence act on E[J] across generations, which is the key simplification.

Flattening the table into one vector

Arrange the four entries of a two-deme table in row order:

j=(J11,J12,J21,J22)T(C.39)

Flattening changes the addressing, not the biology. Each coefficient in (C.31) becomes one entry of a larger matrix. For the M in (C.32a), that matrix is:

B=M⊗M=(0.640.160.160.040.080.720.020.180.080.020.720.180.010.090.090.81)(C.40)

The symbol ⊗ denotes a Kronecker product. Here it simply lists the products of the two parental source weights. For example, row 2 describes destination pair (1,2): its weights are 0.8·0.1, 0.8·0.9, 0.2·0.1, and 0.2·0.9. Multiplying Bj reconstructs the flattened K.

Let Dn be diagonal, with entry 1−1/ni at the address of Jii and 1 at all off-diagonal addresses. Let c contain 1/ni at diagonal addresses and zero elsewhere. For the ten-copy example:

Dn=diag(0.9,1,1,0.9)(C.41a)
c=(0.1,0,0,0.1)T(C.41b)

The operator and its affine recurrence are:

A=αDn(M⊗M)(C.42)
E[jt+1]=AE[jt]+c(C.43)

Apply B first, multiply each output coordinate by its diagonal damping factor, then by α, and finally add c. This reproduces all entries of (C.38). The constant vector determines the fixed point but disappears when tracking the error from that fixed point. Thus recursion_relaxation_time() needs the spectral radius of A, not the fixed point itself. For d demes there are d2 ordered pair addresses, hence a d2-by-d2 matrix. General dense eigensolver cost grows roughly as (d2)3=d6, which motivates the 24-deme guard.

Within- and pooled heterozygosities are linear combinations of these identities. But D and GST are ratios of random heterozygosities: E[f(J)] is generally not f(E[J]). The identity timescale therefore informs their burn-in; it does not prove that every statistic has exactly the same relaxation or sampling-error behavior. Allele richness and spectrum statistics require further caution.

Why a one-lineage migration gap is not enough

Migration alone follows the location of one ancestral lineage. Identity also depends on what happens to two lineages. They must reach a common ancestor, or mutation must erase their shared identity. A location can become well mixed before two particular ancestral lines have coalesced.

For the equal-size island matrix, the nonconstant migration eigenvalue is 1−md/(d−1), so its positive gap is md/(d−1). With five demes and m=0.0001, the inverse gap is 1/0.000125=8000 generations. This is far below the approximately 19,693-generation identity scale in (C.9). In the low-migration regime their ratio is roughly d/2, not a universal factor for every topology. For asymmetric or periodic matrices, even the interpretation of a "smallest nonzero eigenvalue" needs care; the symmetric island comparison is the simple example, not a general algorithm.

What the coalescence approximation assumes

Two lineages currently in different demes each migrate with probability m. To first order in small m, one migrates into the other's deme at rate 2m/(d−1). Simultaneous migration contributes terms of order m2 omitted from that approximation. The reciprocal gives the approximate time (d−1)/(2m) for the pair to meet in a deme.

Meeting in a deme is not yet choosing the same parental copy: they can separate again. The classical island coalescence timescale adds the total-population term to obtain (C.6). The addition can be derived using two ancestral states:

different demes -- rate 2m/(d-1) --> same deme -- rate 1/n --> coalesced
different demes <-- rate 2m -------- same deme

Here n is the equal per-deme copy count. Let Tsame and Tdifferent be the expected remaining times to coalescence from those states, ignoring mutation while deriving the coalescence part. In the continuous-time, small-migration approximation:

  1. A pair in different demes waits on average (d−1)/(2m) to enter the same-deme state. Thus Tdifferent=Tsame+(d−1)/(2m).
  2. In the same-deme state, coalescence has rate 1/n and separation has rate 2m. Write r=1/n+2m for their total. The mean wait to the next event is 1/r. With probability (2m)/r the event is separation, requiring an additional Tdifferent. With probability (1/n)/r coalescence ends the wait. Consequently Tsame=1/r+(2m/r)Tdifferent.
  3. Multiply by r and rearrange to get Tsame/n=1+2m(Tdifferent−Tsame).
  4. Substitute the difference from step 1. The right-hand side becomes 1+2m(d−1)/(2m)=d. Therefore Tsame=nd=ntotal.
  5. Step 1 now gives Tdifferent=ntotal+(d−1)/(2m), the T used in (C.6).

The model explicitly allows separation before coalescence; the total-population term is not simply one local waiting time. These waiting-time equations are exact for the stated continuous-time approximation, not for arbitrary probabilities in the discrete-generation engine. Using this pairwise mean as the inverse slow decay rate is itself an approximation.

Mutation supplies another route to loss of identity. For two copies the exact survival is (C.35), with loss 2μ−μ2≈2μ. Treating coalescence and mutation as small independent hazards gives an effective rate 1/T+2μ and its reciprocal (C.7). This explains both why rates add and why the implemented closed form is approximate.

How precise is the reported value?

For everyone. A statistic that has stopped trending still varies from generation to generation. Neighboring generations have shared ancestry and similar frequencies, so they are not independent observations. Counting every generation as independent can make an average's error bar much too small. The following derivation explains the correction.

Averages, deviations, and correlated observations

Within a post-burn-in window, write the statistic values as Y1,…,YW. The subscript counts observations within this window, not absolute generations. Their average is:

Y¯=1W∑u=1WYu(C.44)

The bar means average; ∑ means add the indicated terms. For (0.2,0.4,0.6), this gives 0.4. Let σ2 be the variance of a stationary individual observation, and ρh the correlation between observations separated by h generations. Stationarity here means that the distribution and lag correlations no longer depend on the absolute starting generation.

Expand the square of the centered sum. There are W individual variance terms. For each separation h, there are W−h distinct pairs, and both orders of each pair appear:

Var(∑u=1WYu)=Wσ2+2σ2∑h=1W−1(W−h)ρh(C.45)

For W=4, lag 1 has pairs (1,2),(2,3),(3,4), lag 2 has (1,3),(2,4), and lag 3 has (1,4). This is the origin of the factor W−h, not an arbitrary weight. Dividing the sum by W divides its variance by W2:

Var(Y¯)=σ2W[1+2∑h=1W−1(1−hW)ρh](C.46)

If every ρh=0, only the familiar σ2/W remains. For a long window with correlations that decay fast enough for their sum to exist, the bracket approaches the integrated autocorrelation factor:

τint=1+2∑h=1∞ρh(C.47)

The convention includes the leading 1 and both lag directions. Some references define this quantity with a different factor of two; use (C.47) when comparing values here. For observations at every generation, τint can be interpreted as generations per equivalent independent observation. It is not the model-derived slow-mode relaxation time τ. The former depends on the statistic and its whole correlation curve; the latter is a model timescale.

Replace the actual observation count by its equivalent-information count, the effective sample size:

Weff≈Wτint(C.48)

Taking the square root of (C.46), with the long-window approximation, gives the standard error of the mean:

SE(Y¯)≈σWeff=στintW(C.49)

For W=10000, σ=0.1, and τint=100, the effective count is only 100. The standard error is 0.1/100=0.01, not the independent-draw value 0.1/10000=0.001. Individual values still vary on scale 0.1. The standard deviation describes that spread; the standard error describes uncertainty in their average.

Why the estimator uses more than lag 1

The estimator matters. A single-lag estimate (the correlation of neighboring values) gives the full sum only under an assumed geometric correlation curve, as for a stationary first-order autoregression. If ρh=rh with |r|<1, the geometric series gives:

τint=1+2r1−r=1+r1−r(C.50)

A mixture need not follow that curve. Consider:

ρh=0.9(0.5)h+0.1(0.99)h(C.51)

Its lag-1 correlation is 0.549. Substituting that one number into (C.50) gives about 3.435. But summing both geometric tails gives 1+2(0.9+9.9)=22.6. The small slow component contributes most of the long-run uncertainty even though its lag-1 contribution is only 0.099. Lag 1 alone cannot identify the tail's shape.

In the repository's seeded two-mode measurement whose true τint is 469, the single-lag formula gave about 75 and Geyer's estimate gave 438. Those are results for one measured series, not deterministic guarantees for all series with slow modes.

geyer_window_statistics() implements the initial positive sequence method. First center the observed values and estimate their lag correlations:

ρ^h=∑u=1W−h(Yu−Y¯)(Yu+h−Y¯)∑u=1W(Yu−Y¯)2(C.52)

A hat means an estimate from finite data. The implementation uses this shared-denominator normalization, with ρ^0=1, not a separate W−h divisor at every lag. It computes the sums using a zero-padded fast Fourier transform; that changes computational cost, not the sums being estimated. A constant window is handled separately to avoid a zero denominator: its estimated spread and standard error are zero and its effective count is W. A finite constant sample is not proof of global equilibrium; burn-in and the other diagnostics still matter.

Pair consecutive lag estimates:

Γ^j=ρ^2j+ρ^2j+1(C.53)

Starting at j=0, keep complete pairs until the first nonpositive pair. If the last kept index is q, calculate:

τ^int=max(1,−1+2∑j=0qΓ^j)(C.54)

The empty retained sum is zero. Why the −1? The first pair includes ρ^0=1; doubling all pairs counts it twice, so subtract one to recover the leading 1 in (C.47). For pair sums 1.8,1.1,0.4,−0.05, retain only the first three. Their sum is 3.3, giving −1+2·3.3=5.6. The lower clamp of 1 prevents crediting a negatively correlated sample with more effective observations than actual observations.

The method limits noisy long-lag contributions rather than literally summing every estimated lag. Initial-positive-sequence theory is motivated by suitable reversible stationary processes; using it for these recorded statistics remains an estimation procedure, not a proof that every slow component has been found. Too little evidence can hide a tail from this estimator too.

See the finite-evidence limit for why an apparently quiet window is not a proof of equilibrium.

The code uses the sample standard deviation s=∑u(Yu−Y¯)2/(W−1), then reports Weff=W/τ^int and SE^=s/Weff. The finite-window weights in (C.46) explain the exact variance; (C.52)–(C.54) describe the particular estimator actually used.

Turning precision into a stopping test

Let γ be confidence, and Φ the cumulative distribution function of a standard normal random variable. The two-sided critical value is:

zγ=Φ−1(1+γ2)(C.55)

For γ=0.95, each tail has probability 0.025 and the quantile is 0.975, giving zγ≈1.959964. The approximate interval is Y¯±zγSE^. Its half-width must not exceed ε:

SE^≤εzγandWeff≥50(C.56)

At precision 0.01 and 95% confidence, the target standard error is about 0.005102, not 0.01. With s=0.1, at least approximately (1.959964·0.1/0.01)2=384.15 effective observations are needed for the error target, in addition to the effective-count floor. If τint=100, that suggests roughly 38,415 recorded generations. The monitor checks observed estimates, not this forecast.

A per-statistic statistic_precision overrides the shared target. For unbounded watched statistics configured for relative precision, the default absolute tolerance is replaced by εmax(1,|Y¯|); for a count averaging 200 with precision 0.01 this permits a half-width of 2. An explicit per-statistic override instead retains its supplied absolute units.

Nominal 95% coverage describes a statistical procedure under its assumptions, not a 95% guarantee attached to each realized interval. Repeated adaptive checks, approximate correlations, and inadequate burn-in can affect coverage. The implementation does not claim a simultaneous 95% guarantee across all watched statistics or all check times.

Reading the evidence and the start-versus-end diagnostic

Every scalar run's report.json carries the evidence either way, in window_statistics, one entry per statistic recorded: mean (the window average, the estimate to read), standard_error, standard_deviation, effective_sample_size, window (its length), window_start and window_end (the generations it spans), burn_in, estimator, noise_adequate (whether the requested precision was reached), the target_standard_error and minimum_ess it was judged against, and geweke_z. Every statistic shares the one window, so the entries are consistent whichever statistic decided the stop. geweke_z compares the start of the window with its end in units of their combined standard error; an absolute value above 3 (the Expert Setting start_drift_alert_z) means the averaging may have begun before the model forgot its starting state, so the burn-in may have been too short. It is a diagnostic only: it never stops or continues a run, and it is absent for a window too short to split.

The start-versus-end statistic compares the first 10% of the window with its last 50%, using an autocorrelation-corrected standard error for each segment:

zstart/end=Y¯start−Y¯endSEstart2+SEend2(C.57)

For means 0.45 and 0.40 and segment standard errors 0.01 and 0.012, the denominator is approximately 0.01562, giving z≈3.20. This exceeds the default alert threshold. The two segment errors are added in quadrature, not simply added. The diagnostic treats their cross-dependence as negligible; it is not a definitive equilibrium test. If both errors are zero, the code returns zero for equal means and signed infinity for unequal means.

Projecting the length of an unfinished run

A run that reaches its cap without the requested precision also reports projected_generations: how long the run would have needed. The standard error of a mean falls approximately as one over the square root of the window length if its underlying noise and correlation stay the same. Writing se for the current standard error and s* for its target, the required precision window is:

Wprecision=W(ses*)2(C.58)

To derive this, use s*=seW/Wprecision, divide by se, square, and solve for the new length. Halving the standard error requires four times the window; reducing it by ten requires a hundred times the window. The effective-count floor separately requires:

WESS=50τ^int(C.59)

The reported projection uses the longer requirement, rounded up and added to the start:

tprojected=b+⌈max(Wprecision,WESS)⌉(C.60)

For W=10000, se=0.02, s*=0.005, and τ^int=100, the two requirements are 160,000 and 5,000. If b=100000, the reported projection is generation 260,000. It is a planning estimate, including the implementation's endpoint convention, not an exact promise about the next successful check. Unknown slow modes can change the forecast. At zero target error there is no finite nonzero-noise projection.

The monitor makes the same projection after every check that fails and logs a warning once, as soon as the projection passes the cap, so a run that cannot finish in time says so long before it ends. The command line repeats it in the cap note: "At this precision D needs about N generations; more loci or more replicates reach it faster". The CLI prints the watched statistic's own line after every run; the GUI's Run card tooltip shows the same numbers. Under convergence_combinator: all, the overall projection takes the latest of the watched-statistic projections; under any, it takes the earliest available one.

Batches: replicates that average

For everyone. A batch (n_replicates above 1) reaches the precision by averaging twice: each replicate averages over time after its own burn-in, and the batch then averages across replicates. A replicate has no precision check of its own. It burns in, averages for its window, and stops; its window mean is the number it contributes. The last generation's value, one noisy draw, no longer stands in for the replicate.

For analysts. How long a replicate should average is a trade. A long window makes each replicate precise and needs few replicates; a short one needs many. fim matches the window to the batch (replicate_averaging_window):

  1. The first wave (8 replicates by default) averages for a guess, 20 relaxation times.
  2. The wave's windows estimate the variance σ2 and integrated autocorrelation factor τint of each watched statistic; the planner averages each quantity across the wave.
  3. The planner chooses an intended replicate count R (twice the wave width, or replicate_minimum if larger) and computes the per-replicate error target and averaging window derived below. The longest requirement among watched statistics sets the window, held between 5 and 100 relaxation times.
  4. Every later replicate averages for that window. A later replicate runs up to the shortest window it could receive and waits for step 3, so the result is the same on every backend. The wave width is a number in the configuration, not the processor count, so it is the same on every machine too.

Each replicate's window is recorded in its manifest. With precision_method: planned_replicates the batch runs exactly n_replicates replicates and the window is sized so their interval is plus or minus the precision.

The assigned window is a generation span. Consistently with the monitor's inclusive endpoints, a replicate starting at b stops at b+Aw and can include Aw+1 observations. This one-observation difference is negligible for the planning approximation, but matters when reproducing the exact schedule.

For ordinary mean-of-values statistics, summary.json reports the mean of the replicates' window means with its Student's-t interval. For D and GST under the value of means, the replicates' window means of H_S and H_T are pooled first and the statistic is taken once; averaging the statistic inside each replicate and then across replicates would give a number that depends on the window length. The interval then comes from the delta method over replicates. The early stop of a batch judges the per-replicate values, a close approximation of the same interval.

The across-replicate interval

Let Zr be one replicate's post-burn-in average, and let R be the number of completed independent replicates. Average those summaries with equal weight:

Z¯=1R∑r=1RZr(C.61)

Independence is between replicates with separate random streams, not between the correlated generations within a replicate. For R≥2, estimate the spread of replicate summaries:

sZ2=1R−1∑r=1R(Zr−Z¯)2(C.62)

Subtract the mean, square each departure, and add them. The divisor R−1 accounts for estimating the mean from the same data; the departures must sum to zero. The standard error of Z¯ is sZ/R. With confidence γ, the interval is:

Z¯±t(1+γ)/2,R−1sZR(C.63)

The t here denotes a Student's-t critical value, not a generation index. The second subscript is its degrees of freedom. At 95% confidence and R=25, the critical value is about 2.064. If Z¯=0.4 and sZ=0.1, the standard error is 0.02 and the interval is approximately 0.4±0.04128, or (0.35872,0.44128). More variable replicate means require either more replicates or longer within-replicate windows.

The Student interval is exact for independent normally distributed summaries of equal variance; its use with finite simulation summaries, adaptive windows, and early batch stopping is approximate. Equal weighting makes every replicate estimate count once, even when window lengths differ. Weighting by total generations would instead give longer replicates more influence.

Solving for a matched averaging window

For planning only, suppose each replicate mean has the same standard error slane. Setting the batch half-width equal to the requested precision gives:

ε=t(1+γ)/2,R−1slaneR(C.64)

Multiply by R and divide by the critical value:

slane=εRt(1+γ)/2,R−1(C.65)

Now use (C.49) for a replicate with averaging-window length Aw: slane2=σ2τint/Aw. Solving for length gives:

Aw=τint(σslane)2(C.66)

For R=25, ε=0.01, γ=0.95, σ=0.1, and τint=100, the lane target is approximately 0.05/2.064=0.024225. The resulting window is approximately 100(0.1/(0.05/2.064))2=1704.0384 generations, using the displayed rounded critical value throughout. If the model relaxation time is 100 generations, this is about 17.04τ, between the default clamps of 5τ=500 and 100τ=10000. The planner rounds the chosen length upward to a whole generation.

The first wave's noise estimates are only estimates. For every watched statistic the planner averages window variances and autocorrelation factors across that wave, uses their product in (C.66), and takes the largest result. It does not fit a new biological timescale. The cap's available post-burn-in space can shorten an automatic window further. An explicitly fixed window is not silently clamped; a run that cannot finish it before the cap reports that fact.

Under precision_method: planned_replicates, the intended count is the requested n_replicates; under early stopping, it is a planning target, not a promised final batch size. The realized interval must still be checked and reported. This is why a matched window is not itself a precision guarantee.

Which average? Two forms for each differentiation measure

For analysts. D and GST are functions of two heterozygosities, X=f(HS,HT). Averaging a nonlinear function need not equal applying it to averages. This is a nonlinear averaging gap; Jensen's inequality gives a direction only when the needed convexity or concavity assumptions hold. No such direction is assumed here. A run can target either of two quantities:

  • Mean of values (default): the average of X over the evidence window. It is what a sampled population shows on average, and what published replicate means are.
  • Value of means: f of the window's average HS and HT. It is the form obtained by substituting predicted mean heterozygosities into a formula. Its standard error comes from the delta method, using the covariance and autocorrelation of both heterozygosities.

Choose with convergence_estimate: mean_of_values, value_of_means or auto. The choice drives the stop, the headline mean and the interval. Whatever the choice, each of D and G_ST in window_statistics also carries mean_of_values and value_of_means (each {mean, standard_error}), selected_form, and undefined_generations: the window generations in which the statistic had no value, which the first form drops (G_ST where H_T is zero). The value of means can remain defined when some individual values are not, so auto selects it when any generation is undefined or when more than 1% of the window has a denominator below 0.01. Statistics that are not functions of the identities have one form.

In the measured single-locus example motivating this option, the gap was about 0.011 for D and 0.0001 for GST, near the default precision for D. Those are not universal constants. With independent pooled loci and a well-behaved denominator, the gap commonly shrinks on the order of the reciprocal locus count.

Calculate both forms from the same observations

Use Su=HS,u and Tu=HT,u for one window observation; these symbols are heterozygosities, not copy totals. Let S¯ and T¯ be their respective window averages. The two estimators are:

X^mean of values=1W∑u=1Wf(Su,Tu)(C.67)
X^value of means=f(S¯,T¯)(C.68)

Consider two equally weighted observations with (S1,T1)=(0,1/2) and (S2,T2)=(1/2,3/4). These are attainable two-deme states: private fixed alleles give the first pair, and two private equally frequent alleles per deme give the second. For GST the function is:

fG(S,T)=1−ST,T>0(C.69)

Its observed values are 1 and 1/3, so their mean is:

G^mean of values=1+1/32=23(C.70)

But S¯=1/4 and T¯=5/8, giving:

G^value of means=1−1/45/8=35(C.71)

The difference 2/3−3/5=1/15 is not rounding error. The first divides each observation by its own total diversity before averaging. The second pools the diversity components before dividing. More observations reduce sampling uncertainty in each target; they do not force the two population targets to coincide.

For Jost's statistic, write ad=d/(d−1):

fD(S,T)=adT−S1−S,d>1, S<1(C.72)

Apply the same distinction to (C.72). In the particular two private-allele observations above, both D forms equal one. This equality is a feature of that example, not a general identity for D.

For a nonzero D gap, keep two demes but use observations (S,T)=(0,1/2) and (1/2,1/2) instead. The first again has distinct fixed alleles; the second has identical rows (1/2,1/2) in both demes. The two D values are 1 and 0, averaging to 1/2. Their component means are (S¯,T¯)=(1/4,1/2), so applying (C.72) once gives 2(1/2−1/4)/(1−1/4)=2/3, a different target.

Undefined observations need special care. Dropping generations with T=0 from (C.67) means the mean-of-values GST describes only generations where it is defined. Equation (C.68) can still use their (S,T)=(0,0) contributions in the component means. If every generation has T=0, then T¯=0 and that form is undefined too. It must not be interpreted as automatically providing a finite answer.

The delta method: propagate uncertainty through a ratio

The first-order change of a smooth function near (S¯,T¯) is:

f(S¯+δS,T¯+δT)−f(S¯,T¯)≈fSδS+fTδT(C.73)

fS and fT are partial derivatives: rates of change when one input changes while the other stays fixed. Evaluate both at the estimated component means. The approximation replaces the curved surface locally by a plane. Applying variance to this linear approximation gives:

Var[f(S¯,T¯)]≈fS2Var(S¯)+fT2Var(T¯)+2fSfTCov(S¯,T¯)(C.74)

Covariance measures whether the component means rise together. Ignoring it would treat two measurements of the same populations as unrelated. Autocorrelation also matters: the variances here are variances of means, not of individual generations.

For (C.69), differentiation gives:

(fG,S,fG,T)=(−1T,ST2)(C.75)

The first derivative is immediate because T is fixed. For the second, differentiating T−1 gives −T−2; the minus in −ST−1 cancels it. For (C.72), the quotient rule gives:

(fD,S,fD,T)=(adT−1(1−S)2,ad1−S)(C.76)

For its first component, differentiating (T−S)/(1−S) produces numerator −(1−S)+(T−S)=T−1 over (1−S)2. These derivatives reveal why a small denominator can amplify input errors.

The code avoids separately estimating every cross-lag covariance by constructing a linear series:

Lu=fSSu+fTTu(C.77)

It applies the same Geyer estimator to Lu. The standard error of L¯ approximates the error of f(S¯,T¯) by (C.73), including component covariance and temporal correlation. It then reports the nonlinear value f(S¯,T¯) as the mean, not the generally different mean of Lu.

At (S¯,T¯)=(1/4,5/8) the GST derivatives are (−1.6,0.64). Suppose the component means have variances 0.0004 and 0.0009 and covariance 0.0003. Equation (C.74) gives 2.56(0.0004)+0.4096(0.0009)−2.048(0.0003)=0.00077824, with standard error about 0.027897. This is an illustrative covariance calculation, not an error estimate from the two-observation example. The delta method is local and approximate; near undefined ratios, linearization may be inadequate.

For batch value-of-means summaries, replace the temporal component observations by the per-replicate component means. Average those components across replicates first, then apply f once. Apply covariance propagation across independent replicates for its interval. Averaging the per-replicate nonlinear values instead targets a different quantity.

Checking the numbers yourself

  • dev/bin/relaxation-table prints the identity operator's gap timescale beside the scalar approximation and the migration gap for six reference models. The unit tests in test_defaults.py fail if the closed form is off by more than 5%.
  • test_burn_in_monitor.py pins the schedule (burn-in, first check, doubling) and the stop rule on exact series, and test_window_statistics.py checks the estimator against hand-worked values and known autoregressive series.
  • test_convergence_rule_calibration.py checks committed calibration evidence and seeded scenarios, including Golden Part VI and the Dear-Nolan low example. Its slow checks exercise the combined simulation and stopping rule.
  • test_convergence_docs.py checks that the documented burn-in and cap formulas contain the shipped policy constants, including their TEX rendering here.

These checks address different claims. Matching the table verifies the policy calculation; matching an analytic covariance series verifies an estimator; matching an equilibrium simulation adds scientific evidence for the combined system. None substitutes for the other two. Fixed-seed checks can be reproduced without rerunning until a favorable sample appears.

Limits

Each limit links back to its main explanation; that explanation also links here so the qualification can be read in context.

Scalar approximation limit

The scalar closed form is an approximation for the equal-size symmetric island model, checked within 5% of the identity operator in the reference tests. It is not an exact discrete-generation formula for all parameter values.

Return to units and the scalar island approximation.

Matrix and size limit

Unequal sizes do not merely substitute their sum into that scalar formula. They use the size-weighted scalar migration matrix or the explicitly supplied matrix and the d2 identity eigenproblem, provided d≤24. An explicit matrix is not reweighted by sizes. Larger cases needing that route require explicit run limits and cannot receive this model-derived timescale.

Return to the choice of timescale calculation. The flattened operator derivation explains why the eigenproblem grows so quickly.

Slowest-locus limit

The slowest locus is selected by its smallest mutation rate within this identity approximation, not by observing that every possible statistic has settled.

Return to the mutation-rate choice in the scalar approximation.

Empirical-cap limit

The 200,000 floor is measured from two regimes, not derived from first principles. A third, faster-mixing regime needed far less (12,000), so the floor has real margin, but a configuration not yet measured could need more before its precision is reached, in which case the run reports the cap honestly, with the average and error bar it has, rather than a false convergence.

Return to the safety-cap calculation.

Check-scheduling limit

Checks occur at approximately doubled window lengths, not every generation, to keep checking cheap. If precision first becomes adequate between checks and remains adequate, the next check can require nearly twice as much evidence, apart from integer endpoint effects. Estimated precision need not improve monotonically.

Return to window boundaries and check scheduling.

High-migration evidence limit

The Dear-Nolan high-migration scenario (100 demes of 2,000 gene copies) is not covered by the cited replicated measurement; at that measurement's backend and hardware it cost about 0.4 seconds per generation. That is not a current cross-backend performance guarantee. Its scalar timescale is dominated by mutation (about 499 generations). The dense 100-deme recursion exceeds the implementation guard, so that scale should not be described as a fresh direct eigensolver check.

Return to the scalar timescale and its calculation routes.

Finite-alleles limit

The finite-alleles mutation model changes the mutation term and is not covered by the infinite-alleles derivation: independent mutations can produce matching labels. A timescale supplied by the current defaults must therefore be read as a heuristic for that model.

Return to the drift-and-mutation identity derivation.

Stochastic-migration limit

Stochastic migrant amounts also need a second-moment qualification. Conditional on a realized mixing matrix, (C.30) applies, but averaging generally requires E[MJMT], not E[M]JE[M]T. In particular, the two weights for a same-deme pair share a random migrant fraction. The defaults do not build that augmented second-moment operator; do not interpret their timescale as an exact recursion for this variant.

Return to the two-parent migration-weight derivation.

Finite-evidence limit

A constant or apparently stationary evidence window can miss rare transitions. The error bar is conditional on the stationarity and correlation assumptions used to estimate it. Increasing the effective-count floor cannot prove those assumptions.

Return to the autocorrelation estimator and its cutoff.

Allele-label stationarity limit

Infinite-alleles stationarity refers to frequency structure and statistics modulo allele relabeling. Absolute newly assigned allele IDs keep increasing when mutation continues; those labels do not have a stationary registry distribution.

Return to what the pairwise identity table measures.
